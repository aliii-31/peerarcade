# Draft: v0.2.0 — P2P Multiplayer

**Unpublished release draft. Current recommendation: GO following maintainer
manual desktop sign-off.** See the [QA report](../qa-v0.2.md) for exact code, evidence and
release gates. This document is not a release announcement.

## Included capabilities

- Hyperswarm peer discovery and encrypted peer connections inside the Bare worker.
- Invitation-based two-player rooms with host/guest roles, admission handshake,
  create/copy/join/leave controls and connection status.
- Host-authoritative Tic-Tac-Toe using the independent rules engine: host X,
  guest O, validated moves, state revisions, duplicate protection, wins and draws.
- Electron game interface with a responsive board, turn/outcome messages,
  disabled unavailable moves and authoritative accepted-state rendering.
- Existing local worker health checks and opt-in developer discovery mode.

A departed player ends the match. Rejoining creates a new empty match. Invitations
are bearer secrets, not authenticated player identities. Both peers must run
compatible current code.

## Verified evidence

On macOS 14.5 arm64, Node 22.23.3/npm 11.9.0:

- Clean dependency installation and syntax checks passed.
- All **82 automated tests passed**; zero audit vulnerabilities.
- Real independent Electron/Bare processes connected over Hyperswarm and agreed
  after every move in an X win and a draw. Invalid/duplicate/stale requests,
  third-player rejection, fresh-match rejoin, normal shutdown and injected guest
  termination were checked.
- Separate production BrowserWindow diagnostics loaded and exited normally,
  including Bare exit code 0. These are startup/cleanup checks, not GUI gameplay.

The maintainer subsequently confirmed manual desktop product verification and
approved proceeding toward release. This is separate from automated evidence;
no detailed scenario results, screenshots, environment or exact manual-test commit
were provided. No agent-performed GUI pass is claimed.

## Known limitations

- Agent computer-use access was denied during QA. Maintainer sign-off satisfies
  the release gate, but does not establish separate results for each mouse,
  keyboard or clipboard scenario. Headless tests remain distinct from GUI evidence.
- Running simultaneous instances with one shared Electron profile reproducibly
  emits Chromium cache errors. Independent disposable profiles avoided these
  errors in QA. No crash was observed; visual gameplay impact is unresolved.
- Socket error events around tested departures were handled and followed by
  expected cleanup. This does not establish resilience to all network failures.
- No cross-device, NAT/firewall matrix, Windows/Linux, long-running reliability,
  packaged-distribution or independent security-audit coverage is claimed.
- No automatic reconnect, saved games, host migration, accounts, public
  matchmaking, rematch controls, leaderboards or Connect Four.
