# v0.3.0 — Reliability & Recovery

**Unpublished draft. Release recommendation: GO with maintainer acceptance of
the remaining desktop recovery verification gap.** See the
[QA report](../qa-v0.3.md) for exact revisions, commands and evidence.

## What's new

- Temporary P2P reconnection while the original host and guest workers remain alive.
- Session-bound resume credentials in addition to encrypted transport and invitation
  proof: possessing the invitation alone cannot reclaim another guest's reserved slot.
- Restoration of the original authoritative match ID, accepted history/board,
  revision, turn and outcome. Request deduplication survives transport loss.
- Bounded retries and a 60-second recovery window; clear failure and intentional
  Leave cleanup. Moves stay disabled until accepted state is restored.
- Expanded resilience QA: three recoveries in one match, uncertain accepted and
  unaccepted moves, reserved-slot rejection, retry exhaustion, room recreation,
  timer/socket accounting and worker shutdown checks.

## Verification

All 92 existing automated tests pass. Syntax checks, real Electron/Bare/Hyperswarm
network testing and dependency audit pass (zero reported vulnerabilities).
Four production windows passed startup/exit diagnostics; isolated profiles avoided
shared-profile Chromium cache warnings. Version metadata is 0.3.0 with unchanged
dependencies. No production behavior was changed by the QA preparation itself;
recovery was implemented in PR #26.

Network fault injection used actual sockets on one Mac, not actual Wi-Fi outages
or cross-device networks. Visible desktop recovery remains unverified because
computer-use access was denied; the maintainer has accepted this gap without claiming specific GUI tests passed. v0.2 manual
sign-off is not evidence for this feature.

## Known limitations

- Both peers must use compatible protocol v2; v0.2.0 protocol v1 cannot join.
- Both original workers must remain alive. No persistent sessions, process-restart
  recovery, host migration or offline play.
- Invitations and resume credentials prove possession, not personal identity.
- Recovery is bounded; a failed session requires Leave and a fresh room/match.
- Shared Electron profiles can produce Chromium cache warnings. Separate profiles
  passed the bounded startup check; long-running shared-profile behavior is unverified.
- Cross-device, restrictive NAT/firewall, actual network partition, Windows/Linux
  and long-duration soak coverage are not claimed. No packaged installer is added.

No tag, merge or GitHub release is performed by this preparation.
